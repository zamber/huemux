# Settings UI token generator has ~15 bits of entropy (vs. server's 26 bits)

**Severity:** `high`

**Category:** `security`

**Found by:** exploratory proofing run, 2026-08-02

## Summary

The Settings page's "Suggest token" button uses a hardcoded 32-word list and picks 3 words, yielding log2(32³) = 15 bits of entropy (~32,768 possibilities). The Go server's `GenerateToken()` uses a 384-word list producing ~26 bits (~67 million possibilities), and the auth rate limiter (10 failures/min/IP) was sized for that 26-bit threat model. A token generated by the UI is brute-forceable in hours.

## Affected Files

- `web/settings.js:25-30` — 32-word hardcoded list
- `web/settings.js:38-46` — `suggestToken()`: 3 words from 32 choices
- `internal/appconfig/wordlist.go:1-400` — 384-word server list
- `internal/appconfig/token.go:64-78` — `TokenEntropyBits` documents the 26-bit design
- `internal/server/auth.go:26-29` — rate limiter sized for 26-bit tokens

## Evidence

```javascript
// settings.js:25-30 — 32 words
const WORDS = ["otter","badger","falcon","garden","hammer","island",
  "jungle","koala","lizard","magnet","napkin","orchid","pebble","quartz",
  "rabbit","salmon","thistle","umber","velvet","walnut","zenith","anchor",
  "branch","celery","dagger","embers","flask","glider","herald","kernel",
  "marble","nectar"];
```

```javascript
// settings.js:38-46 — 3 words, 15 bits
function suggestToken() {
    const buf = new Uint8Array(3);
    crypto.getRandomValues(buf);
    const out = [];
    for (let i = 0; i < 3; i++) out.push(WORDS[buf[i] % WORDS.length]);
    els.authToken.value = out.join('.');
}
```

```go
// token.go:68 — server design assumes ~26 bits with default 3 words
// With the 384-word list: log2(384³) ≈ 26 bits
```

## Why It Matters

- 15 bits = 32,768 possibilities. At 10 guesses/min (the rate limit per IP), one device brute-forces the space in ~2.3 days
- Multiple compromised LAN devices (or attacker using multiple source IPs) reduce this to hours
- The Settings page is the path most users will use — the CLI has no "generate token" command
- Users who set a UI-generated token and expose the server to LAN are relying on a 15-bit credential the rate limiter wasn't sized for

## Reproduction

1. Open Settings page in browser
2. Click "Suggest token" next to the auth token field
3. Observe the generated 3-word token — always from the 32-word UI list, never the 384-word server list
4. Calculate entropy: log2(32³) ≈ 15 bits

## Suggested Fix

Option A: Replace the UI wordlist with the server's 384-word list (copy `internal/appconfig/wordlist.go` into a JS constant). The `suggestToken()` function must also allow 3-5 words by default.

Option B: Expose the server's `GenerateToken()` via a `/api/token/suggest` endpoint (loopback-only). This keeps the wordlist in one place.

Option C: Increase the UI wordlist to 384 words and default to 4 words (log2(384⁴) ≈ 34 bits).
